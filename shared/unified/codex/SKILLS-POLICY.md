# Skill library policy

The active catalog contains reusable procedures approved by the owner. Save one-off repairs, task outcomes, machine facts and incident history in existing project notes or the homelab change record.

Add a skill only on an explicit owner request. A candidate must cover a recurring class of work, provide useful tool syntax/scripts/templates beyond ordinary model knowledge, and fit an existing skill when possible. Keep its description to one short trigger sentence. Stage changes for review; publish only after approval.

Hermes stages skill writes under pending/skills. Review with /skills pending and /skills diff ID; approve a justified reusable workflow with /skills approve ID, or reject it with /skills reject ID. Automatic skill-creation nudges and curator rewrites are disabled. Ordinary task permissions and memory learning remain unchanged.

Removed material is recoverable from the private backup repository, branch skills-cleanup-2026-11-05. Recovery is deliberate; archived incident notes are not active instructions.
