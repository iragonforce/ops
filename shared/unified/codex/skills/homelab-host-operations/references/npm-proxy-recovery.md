# NPM proxy recovery

Use when several public names fail together or NPM returns 502 while other Cloudflare-controlled names redirect normally.

1. Reproduce each public symptom with bounded `curl -k -sS -o /dev/null -w '%{http_code}\n' --max-time 10 https://NAME/`; compare a known Cloudflare Access-protected route. Test the NPM container listener from its Docker network, then `docker exec nginx-proxy-manager nginx -t` and inspect bounded NPM startup/error logs. A public 502 alone does not locate the failed hop; an Access 302 may be emitted at Cloudflare before reaching NPM.
2. If Nginx will not start, inspect the exact error's generated `/data/nginx/proxy_host/ID.conf` and the matching stored proxy-host record. A custom `proxy_pass` with a static hostname can make the entire Nginx configuration fail at startup when that Docker DNS name disappears. Check the affected host's configured upstream (`$forward_scheme`, `$server`, `$port`) and whether it is actually reachable; do not assume a syntactically valid config makes the app work.
3. Back up the private NPM database and affected generated configs before changing them. Prefer NPM's supported proxy-host management path so database and generated files stay consistent. If emergency recovery requires an on-disk config fix, update the source record and affected generated files deliberately, validate with `nginx -t`, then verify the master/worker process and listener actually started. A container restart does not necessarily regenerate existing conf files or make a previously failed Nginx master start; a standalone `nginx` invocation can also collide with an already-starting master. Inspect process/listener state before starting or reloading again.
4. Preserve literal Nginx `$variables` through every shell/JS quoting layer. In particular, a double-quoted shell `docker exec ... node -e "...$forward_scheme..."` expands the variables on the host and can write `proxy_pass ://:;`; use a single-quoted shell script or another verified quoting method, and read back the exact stanza before reload.
5. Verify `nginx -t`, a response directly from NPM on its Docker network, and affected public names individually. A 302 to Authentik or Cloudflare Access proves only the proxy/auth boundary, not authenticated app access. Report any app whose configured upstream is still absent separately, and keep rollback paths private without printing database contents or credentials.
