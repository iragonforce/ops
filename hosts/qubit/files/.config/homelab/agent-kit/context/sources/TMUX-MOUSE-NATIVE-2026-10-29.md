# Mouse selection and scrollback, 2026-10-29

User preference: keep tmux pane and Neovim file-tree clicks by default. Shift-drag uses Ghostty's native text selection. Super+Shift+M toggles Ghostty mouse reporting off for plain-drag selection and native terminal scrollback; toggle it on again for pane and Neovim mouse actions. This mode switch is necessary because the terminal sends each ordinary mouse event either to itself or to the application.

On Qubit, Tensor and Nexus, `~/.config/tmux/mouse-interaction.conf` now handles root mouse events. Clicks select panes and reach mouse-aware applications. Wheel and drag events reach mouse-aware applications; shell-pane events do not enter tmux copy mode. The active tmux config sources this file. The config also adds `xterm-ghostty:smcup@:rmcup@` so newly attached Ghostty tmux clients use the terminal's primary screen, which has scrollback. Existing attached clients may need to reattach for that terminal capability change. No client or editor was killed or detached.

Qubit and Tensor Ghostty configs have `super+shift+m=toggle_mouse_reporting`; both passed `ghostty +validate-config`. Tensor's `~/.tmux.conf` had become a clipboard-only regular file while its active server used the older full config. It now links to `~/.config/tmux/tmux.conf`, matching the intended persistent setup. All three running tmux servers sourced their configs successfully. Live option and binding readback showed `mouse on` and the new root click, drag and wheel bindings. No physical mouse interaction was observed; user acceptance is pending.

Log review: no tmux debug log existed in the standard `/tmp/tmux-*` locations on any host. Neovim logs showed no mouse or scroll failure. Qubit had unrelated Mason registry/command errors dated October 27; Tensor had unrelated historical Mason errors and Lua LSP workspace/semantic-token messages; Nexus logs had no relevant errors. These unrelated services were not changed.

Rollback after temporary backup removal: remove the `source-file ~/.config/tmux/mouse-interaction.conf` line from each active tmux config, remove the Ghostty toggle bindings, and reload tmux and Ghostty. Tensor's former `~/.tmux.conf` was a clipboard-only file with `set-clipboard external` and three clipboard terminal-feature entries; recreating that exact drift is not recommended. To restore the prior copy-mode mouse behavior, reintroduce the wheel and drag bindings recorded in `TMUX-MOUSE-HISTORY-2026-10-26.md`. The old clients were left attached, so there is no session/process rollback.
