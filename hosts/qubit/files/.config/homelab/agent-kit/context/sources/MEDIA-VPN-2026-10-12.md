# Nexus media routing through UDR7 Switzerland VPN

## Current status

Completed 2026-10-12. Sonarr, Radarr, Lidarr, Prowlarr, Bazarr, Cleanuparr, FlareSolverr, and qBittorrent use UDR7's existing Switzerland OpenVPN client. An independent IPv4/IPv6 router guard passed controlled VPN-loss tests with all eight services. Household traffic remains on Bell.

- Source: entire `pia-vlan` VLAN 2, network ID `6acc6e01a86514afcbf58f7f`, 192.168.2.0/24.

- Bound qBittorrent to its verified `eth0` interface and 192.168.2.10. Removed its `vpn-verified` startup profile only after the independent guard passed. Its retained peer port is 51413; WebUI is 30200; UPnP remains disabled.

Dedicated legacy iptables chains `NEXUS_MEDIA_VPN` and `NEXUS_MEDIA_VPN6` precede existing UniFi forwarding rules. Local destinations return to UniFi's existing firewall; other Media IPv4 forwarding is allowed to continue only through `tunovpnc1`, otherwise dropped. IPv6 forwarding arriving on `br2` is dropped. Existing UniFi rules are preserved.
- The guard runs before `network-init.service` and `udapi-server.service` at boot, and reconciles its own hooks every two seconds. Router firewall backups are private. Removed only existing Media-source conntrack entries when installing the guard.
- qBittorrent's migrated configuration lacked WebUI username/password entries. Restored the matching existing credentials from Sonarr/Radarr/Lidarr through qBittorrent's authenticated API. No arr credentials were changed. qBittorrent 5.2.4 returns HTTP 204 on successful login; validation accepts this response and then checks authenticated API access.
- Updated the API TLS pin after matching the live certificate to `/data/unifi-core/config/unifi-core.crt` through trusted root SSH. Credential values were never rendered.
- Saved private rollback files and a ZFS snapshot before changing application configuration.

## Operation and limitations

- `nexus-stack@media.service` is enabled for startup, with existing ZFS/mount/network prerequisites. Maintained the same Compose project and persistent data.
- The UDR7 guard is custom root configuration. Router firmware upgrades/factory resets can remove custom units or change tunnel names. Two-second reconciliation repairs missing hooks but is not an atomic guarantee during arbitrary administrative firewall replacement. Stop qBittorrent before router firmware changes; reinstall and repeat outage verification before restarting it. No router or Nexus reboot was performed in this task; actual reboot persistence remains untested.
- Router scripts: `/data/nexus-media-vpn/{apply.sh,watch.sh,rollback.sh,interfaces.conf}`. Verify `systemctl is-active nexus-media-vpn-guard.service`, first-position IPv4/IPv6 forwarding hooks, and the Switzerland tunnel identity after updates.
- Routine online verification from Qubit: `ssh nexus 'sudo python3 /home/iragonforce/network-artifacts-20261012/probe-media-vpn.py --qbittorrent --phase=online'`.
- Repeat the controlled outage from this directory with `python3 verify-media-killswitch.py --qbittorrent` only after confirming independent guard installation. The test interrupts only Switzerland-routed services and always attempts to re-enable the existing VPN.

## Rollback

Stop qBittorrent before removing VPN protection if it was later enabled. Restore only the original Compose and qBittorrent configuration files from Nexus's private backup, preserving the app file's original ownership; recreate the existing media project. Remove only the policy route with the recorded ID. Leave the original Switzerland VPN client enabled as it was before this task.

After stopping qBittorrent, use `/data/nexus-media-vpn/rollback.sh` on UDR7 to disable only the guard and remove its dedicated IPv4/IPv6 chains. Never flush or restore the entire router firewall while UniFi is managing it. Router backups and scripts reside under `/data/nexus-media-vpn/`. Existing household networking and unrelated VPN clients must remain intact. Restoring the original qBittorrent configuration also restores its previously missing WebUI credential entries; retain the current matching credential configuration if keeping the app active.

Official behavior reference: [UniFi policy-based routing](https://help.ui.com/hc/en-us/articles/12566175125783-UniFi-Gateway-Policy-Based-Routing). The live interruption result takes precedence over the advertised kill-switch behavior.
