# void — disposable Arch Linux lab VM

## Use

From Qubit, Nexus or Tensor:

```sh
void on
ssh void
void status
void off
```

`void` with no argument also opens SSH. Inside the guest, `sudo poweroff` performs the same clean shutdown.

- Guest username: **student**. SSH keys only; password login and root SSH are disabled.
- The student account has passwordless sudo inside this disposable guest.
- Working directory: `~/labs`.
- The VM is running at completion. It is not configured to start automatically with Nexus, so it uses no guest RAM/CPU while off.

**All guest disk changes are discarded after power-off**, including source files, installed packages, configuration and history. Copy work out with SCP/Git before shutdown if it should be kept. A normal guest reboot can remain in the same session; use a full power-off/start for a fresh baseline. Suspending/saving the guest is not a reset.

## Resources and storage

| Setting | Value |
|---|---|
| Hypervisor | Nexus, QEMU/KVM through libvirt |
| VM name | void |
| Guest OS | Arch Linux x86_64, no desktop environment |
| Boot target | multi-user.target |
| vCPUs | 1 |
| RAM | 1024 MiB |
| Disk | 8 GiB thin qcow2 |
| Baseline host allocation | Approximately 2.13 GiB on fast |
| Guest root usage | Approximately 2.8 GiB; 4.5 GiB available |
| Baseline | /mnt/fast/vms/void/base.qcow2 |
| Session overlay | base.qcow2.TRANSIENT-void, automatically managed by libvirt |

The small default swap from the Arch cloud image was retained (approximately 512 MiB within the disk) to give CLI compilers limited headroom. Large Java/Haskell builds may exceed this minimal profile.

The baseline uses libvirt's native `<transient shareBacking="yes"/>` disk support. The base is read-only; a writable session overlay is created before the guest runs and deleted after it exits. No host filesystem, USB device, GPU or NAS share is passed through to the guest. No custom deletion hook is needed.

## Network and SSH

- VLAN 5 (docker-vlan), **192.168.5.60/24**, gateway 192.168.5.1.
- Static VM MAC: **52:54:00:56:00:60**.
- UniFi client name/reservation: **void**. Address is outside the verified DHCP range 192.168.5.100–199, with no conflicting reservation or ARP response found before allocation.
- Virtio network through macvtap bridge mode on Nexus `enp6s0.5`; Nexus reaches the guest through its existing VLAN 5 macvlan shim.
- DNS: 1.1.1.1 and 1.0.0.1. AdGuard is not used for this VM.
- `~/.ssh/id_ed25519_void` created separately on each host. Only public keys were copied into the baseline; private keys remain on their originating hosts.
- SSH alias: `~/.ssh/config.d/void.conf`, pinned guest host key: `~/.ssh/known_hosts_void`.
- Qubit and Tensor use their existing `nexus` SSH alias as ProxyJump. Nexus connects directly. If using Qubit away from home, that existing Nexus alias must itself be reachable over Tailscale or an available LAN route; the VM has no separate Tailscale installation.
- Host key was obtained through the local QEMU guest agent and pinned before normal SSH connections.

No `void.homelab.lan` DNS record was created. `ssh void` works through its SSH alias.

## Rollback and baseline maintenance

- To retire the VM: shut it down, verify `virsh domstate void` is `shut off`, then undefine only void. Remove only the VM-specific command, sudo rule, SSH config and UniFi reservation. Keep the base disk until removal is explicitly requested.
- Existing pools, host network interfaces, Docker data and other SSH credentials were not modified by VM provisioning.
- Do not update or commit a baseline while the VM runs. Package installs inside a normal session are intentionally temporary. For a persistent baseline update, power off, save a recovery copy, explicitly enter maintenance with transient behavior disabled, update the tooling, then shut down and reseal with transient behavior restored. Compare the new disk, record its checksum and repeat the clean-reset check before normal use.
- Never attach a host data disk or shared writable NAS tree if the expectation is that every change is discarded by the VM reset. The reset affects the guest disk only.
