## Staged selector and verification (later work on November 24)

- The owner clarified that a read-only audit alone cannot improve the Qdrant collection. The task worktree `/opt/data/workspace/worktrees/ops/chat-memory`, branch `feat/qdrant-chat-memory` from `e2696a3`, contains a **separate write-enabled** `sync-chat` integration. It reuses the existing writer, protected state, Gemini Antigravity plugin, Ollama embeddings, Qdrant collection, MCP and Nexus systemd unit. It does not alter the original compaction exporter, create another provider, collection, scheduler, profile, or notification service.
- Persisted default-profile TUI/CLI/Photon user+final-answer pairs are screened, bounded to 9,000 characters, and eligible only after a plain stop finish, absence of a following failed-turn marker, and two minutes of settling. Other profiles, cron and delegated sessions are excluded. A failed, interrupted or malformed model response stops that batch without cursor advancement. Only screened pairs are sent to Gemini; no tool transcripts, entire chats, rejected findings or private credentials are exported to Qdrant or public Git. The model returns 0–2 technical findings in strict JSON. A second privacy gate checks both the topic and text. Findings are historical-only/low-confidence, deterministically identified, exact-content-deduplicated against previous Hermes findings, then embedded/upserted and read back before a private mode-0600 cursor moves. No automatic pruning. These filters cannot absolutely guarantee that every possible sensitive string is detected.
- Gemini 3.8 Flash High was exercised through the existing authenticated provider client with `HOME=/opt/data`, `AGY_CLI_PATH=/opt/data/.local/bin/agy`, and a synthetic technical pair: two schema-valid findings were returned and accepted by the deterministic validators. This does not imply that Gemini 3.1 Pro became available. At 11:02 EST, native cron readback showed the **existing** read-only auditor `b26206c99ed1` already pointed back to `gemini-3.8-flash`, hourly with provider `antigravity-subscription-directsdk` and `last_status=ok` on its 10:07 run. The intervening update was not performed by this task; actor unknown. The requested Flash target therefore required no duplicate edit. Keep the auditor read-only; the new selector writes separately.
- Four affected test modules passed in the task worktree: 5 new chat tests, 7 completed-compaction regressions, 12 baseline Qdrant memory tests, and 10 heading-parser regressions (34 total). The tests cover failed/unfinished/other-profile/cron/delegated turn exclusion, too-new messages, sensitive and oversized content, schema errors, ID/provenance, interruption recovery, model failure, idempotency and checkpoint integrity. `python3 -m py_compile` and `git diff --check` also passed. The staged unit/timer passed `systemd-analyze verify` against their host-visible source paths, and a read-only check of the live Qdrant collection plus one real Tensor Ollama embedding returned a 4096-dimensional vector; no `hermes_chat` points existed then. The new model path has not yet been exercised against a live settled turn or read back from Qdrant/MCP.
- A separate read of live Nexus at 09:17 EST found the old `qdrant-memory.service` had failed because another update held its existing lock; the timer remained active. A correct-user inbox dry run then returned success. This is a concurrency collision, **not** evidence that the staged selector was deployed or failed. Recheck current service state before deploying.

**Deployment order:** explicitly authorize and publish the verified Git source; compare target checkouts and only fast-forward without disturbing unrelated dirty work; bootstrap `/opt/data/state/qdrant-memory/hermes-chat-checkpoint.json` inside Hermes at the current message ID *before* installing the staged extra ExecStartPost; install the source and updated MCP bridge, systemd service/timer and man page from the same Git revision, run `systemd-analyze verify`/`daemon-reload`, then start and read back the existing service. The timer changes from 15 minutes to one hour after inactivity, with the original path watcher retained. For a live canary, use an actual settled safe default-profile turn, verify the `hermes_chat` exact IDs/content hashes and MCP origin-filtered search/read, then rerun for zero new points. This is not a plan to deploy a partially verified selector without the prerequisite gates.
