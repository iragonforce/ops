# Tensor embedding handoff for Nexus writers — source only

**Objective:** Route all known Nexus `qdrant_memory` embedding callers through the existing Tensor typed queue without changing Qdrant write/checkpoint ownership or admitting real GPU work prematurely.

**Source:** `shared/scripts/tensor_gpu_embedding.py`; call-site switches in `qdrant-memory.py`, `qdrant-memory-hermes-mcp.py`, `homelab-index-ops.py`, `obsidian-index.py`, and `git-snapshot-index.py`. The existing `qdrant-memory.service`, timer and path, existing Qdrant collection, exact-ID/hash readback and per-origin checkpoints remain unchanged. No service or environment was deployed.

**Behavior:** A configured `QDRANT_MEMORY_EMBED_COMMAND` JSON argv array runs a pinned noninteractive Tensor SSH command with input over stdin, not argv. The Tensor endpoint writes a private canonical payload and submits an `embedding_batch` record keyed by revision/model/input digest. The caller polls a protected result for at most 30 seconds and validates revision, digest, dimensions and finite values. Any command failure or timeout raises before Qdrant upsert/query and before cursor advancement; no direct Ollama fallback occurs. Without the variable, the original direct embedding path is unchanged. The source-only `run_admitted()` function does not obtain a GPU reservation and must be invoked only by a future worker holding the shared verified lease. A completed embedding job is not a Qdrant receipt; the Nexus writer remains responsible for the upsert, exact readback and checkpoint.

**Verification:** Four offline handoff tests passed for private payload mode, deduplication, result validation, CLI submit/result, corrupted input and failure retry; three writer/MCP tests passed for a configured but unavailable command failing closed and for original direct-path behavior. Thirty existing `test_qdrant_*.py` tests passed. A Python syntax check covered all modified call sites. No GPU, SSH, Ollama or Qdrant operation was executed by these tests.

**Not production-ready:** There is no deployed protected SSH command, real queue worker, tested Tensor idle/activity authority or shared Ollama/MinerU/Hermes request-level GPU admission. Existing direct Ollama clients outside these five scripts also remain uncoordinated. Keep `QDRANT_MEMORY_EMBED_COMMAND` unset in production until those are verified; Stage 4 dispatch remains disabled. Before a live database migration, back up private queue state without deleting pending jobs. Do not interpret a source-only result as live Qdrant acceptance.

**Rollback:** Revert only these source changes or unset the opt-in command. Preserve all Qdrant points, checkpoints, private payloads and queued jobs; never replace a live queue database with a stale copy. The original direct path remains available only for a deliberate rollback after the collision risk has been evaluated.
