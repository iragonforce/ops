# Candidate-only receipt ↔ bank analytics matching

Date: 2026-11-10 (America/Toronto). Objective: connect validated receipt line-item history to existing Wealthfolio spending evidence without creating another bank expense, retaining unmatched scanned iPhone receipts for later review. Git revisions `6f738cbc49ea` (initial matcher) and `d9c78fbc4ccd` (stale-candidate guard) plus this documentation revision are source authority.

## Source and safeguards

Nexus host `/opt/data/bin/finance-receipt-match` is Git-owned at `hosts/nexus/files/opt/data/bin/finance-receipt-match`, with `man/nexus/finance-receipt-match.1`, tests in `tests/finance/test_receipt_match.py`, and a scoped `inventory/deployments.json` entry. It uses the existing host `/usr/local/sbin/receipt-match-audit` MCP client with Bitwarden-held **read-scoped** `WEALTHFOLIO_RECEIPT_MATCH_READ`; no login password or temporary write token is needed. All statements are processed privately; ordinary output contains only aggregate counts and generic error classes. The only writes are in existing PostgreSQL `bank_activity_snapshot` and `receipt_transaction_matches`, with a **candidate** state. Receipt Wrangler, source mail, Wealthfolio activities and the item/price table are unchanged.

Eligibility: validated, non-duplicate CAD receipts; native Wealthfolio CAD **WITHDRAWAL** of exactly the receipt's amount; date within three days; strong normalized merchant agreement; unique receipt and activity ownership. Ambiguity, conflicting existing links, snapshot drift and disappearing previously staged candidates fail closed. The matcher does **not** assert a candidate is confirmed or that a ledger/snapshot represents complete monthly spending. The existing spending views now contain only this partial matched-activity subset; they are **not budgets**. It intentionally does not infer a bank expense from receipt details or classify transfer-family rows as spending.

## Limits and rollback

No scanned iPhone receipt is bank-linked yet because there is no evidence for its payment activity. Candidate matches require owner/bank review before confirmation; merchant similarity is not sufficient to declare spending comprehensive. Source months/other Wealthsimple accounts and CIBC reconciliation remain incomplete. The new matcher only projects receipt-matched withdrawals; the existing daily/monthly spending views omit unmatched spending and cannot support budget totals. New mail ingestion (522 authenticated CIBC alert rows at this snapshot) remains distinct notification evidence and is not automatically attached to Wealthfolio bank rows.

For rollback, stop this unit's matcher step or restore the previous Git-owned unit/script with guarded drift checks and daemon reload, leaving the working receipt/mail steps intact. Review the exact 10 `match_method='unique_amount_merchant_near_date_v1' AND match_state='candidate'` links and any owner edits/dependencies, delete only those eligible candidate links, then only their orphaned `source_data.parser='finance-receipt-match-v1'` snapshots. Confirm Receipt Wrangler, 17 purchase receipts, 74 items, 74 price rows and unchanged Wealthfolio activities; never remove manually confirmed links or overwrite later writes with the entire pre-match dump. Protected backup/restore details and installed digest receipts remain in the private paths and manifest. There is **no recurring backup/retention** in this change.
