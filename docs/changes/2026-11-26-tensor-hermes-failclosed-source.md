# Tensor Hermes fail-closed model boundary — source-only candidate

**Objective:** Stop the pinned Tensor Hermes custom-provider route from reaching sleeping llama.cpp when required GPU admission fails or is absent. No live Tensor Hermes source, service, wallpaper, queue database, or model was modified by this source change.

**Source:** `shared/patches/tensor-hermes-required-gpu-admission.patch`, against NousResearch/hermes-agent `bf0203a` `hermes_cli/middleware.py`. `shared/tests/test_tensor_hermes_required_admission.py` exercises actual `perform_api_call()` dispatch in streaming and direct mode against a scratch-applied patch. The old fail-open behavior is captured separately in `shared/tests/test_tensor_hermes_middleware_admission.py`.

**Behavior:** For the exact Tensor custom-provider route `http://127.0.0.1:8080/v1`, a single marked `llm_execution` callback must be the outermost middleware. Missing, duplicate, out-of-order, or pre-call raising policies deny *before* provider execution; short-circuiting also fails rather than returning a fake result. A callback cannot substitute a fabricated completion for a failed downstream provider call. Non-Tensor routes keep upstream behavior. The marker is a trusted local registration contract, not authentication or a GPU lease.

**Verification:** The patch applied cleanly to a scratch copy of the installed Nexus Hermes source and matched the reviewed edited file byte-for-byte. Six offline tests passed, covering missing/denying policy, both request modes, concurrency, callback ordering, fake response rejection, and an admitted provider stand-in (which always raises instead of producing a fake completion). Python compilation passed. These tests do not exercise live Tensor's installed source, a plugin loader, owner identity, GPU state, llama sleep, or streaming teardown.

**Remaining gate:** Implement and test the actual mandatory policy callback with the existing lease manager, a sleep-aware identity/VRAM backend, last-holder release after native sleep, and shared Ollama/MinerU admission. Ensure CLI and gateway load the patched source and required callback, protect direct clients, and prove failure behavior before any service restart or wallpaper interruption. A live systemd restart with this patch alone would deliberately deny all Tensor Hermes requests. Stage 4–5 production dispatch remains disabled.

**Rollback:** Delete only this candidate patch and positive tests from the feature branch, or revert their Git commit. No runtime rollback exists yet. Before a future Tensor deployment, retain the exact original pinned `middleware.py`, service/provider settings, and protected lease/queue state separately; restore only the modified source and unit bindings on failure without deleting queued work or outputs.
