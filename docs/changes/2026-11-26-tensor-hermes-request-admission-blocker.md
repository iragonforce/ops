# Tensor Hermes request admission — fail-closed boundary blocked

**Scope:** source-only investigation on `feat/tensor-hermes-request-admission` from the Stage 3 branch at `7d62d7c`. No Tensor GPU, llama endpoint, systemd unit, live Hermes configuration, queue, or daemon was touched. The 10:38 EST cold-wake OOM and failed llama service remain governed by `2026-11-26-tensor-llama-cold-wake-oom.md`.

## Tested result

`shared/tests/test_tensor_hermes_middleware_admission.py` imports the upstream `hermes_cli/middleware.py` and executes the actual `perform_api_call()` function from `agent/turn_api_call.py` (isolated AST extraction to avoid starting the agent). The Tensor Stage 2 `LeaseManager` is real source with a synthetic backend and private temporary SQLite state. The provider stand-in **always raises** `ProviderReached`; it never returns a fabricated model completion. Tests assert that the provider is reached *despite* lease denial, and therefore are **negative-characterization tests**, not a successful admission gate.

Against NousResearch/hermes-agent commit `bf0203a` (the Tensor pinned revision; fetched as immutable GitHub raw source into scratch): **4/4 tests passed**, demonstrating:

- An existing incompatible embedding reservation rejects the Hermes lease, yet downstream provider execution is attempted in both direct and Hermes streaming branches.
- A required but absent trusted process identity denies acquisition, yet provider execution is attempted.
- Two simultaneous incompatible requests both cross the boundary; the existing embedding holder remains intact.
- An unidentifiable GPU backend leaves the lease in recoverable `preparing` state with no holder, yet the model call proceeds.

The same four tests passed against the Nexus running Hermes package's extracted source. The adjacent 152 non-queue Tensor GPU regression tests also passed. The full 165-test GPU run did **not** pass here: six existing queue-test errors/failures arise because this scratch filesystem creates SQLite files mode 0644 even when the process sets umask 077 (reproduced with a standalone SQLite probe). This is not a GPU admission result and the queue source was not changed. This is not a live inference/endpoint test and does not establish safe cold wake, owner inventory, or restoration. Both streaming and non-streaming tests execute `perform_api_call()`'s actual dispatch, with stand-ins that raise; they do not simulate token delivery or prove worker teardown.

## Exact blocker and required upstream change

At `bf0203a`, `hermes_cli/middleware.py::_run_execution_chain()` lines 200–212 catches a callback exception **before `next_call`** and executes `call_at(index + 1, payload)`. Thus a lease's `LeaseError` is logged and ignored, and even a misconfigured admission callback permits the provider call. The `pre_api_request` hook is an observer with failures swallowed; it cannot be substituted. `agent/turn_api_call.py::perform_api_call()` lines 89–139 routes both streaming and non-streaming model execution through `run_llm_execution_middleware()`. No native plugin-only path can promise fail-closed GPU admission while that default skip exists. Do **not** install a lease middleware that returns a fake successful response, treats a hook log as a veto, or throws `BaseException` to evade the handler.

Before implementation, upstream needs an explicit **required, fail-closed `llm_execution` policy** at `_run_execution_chain`: if a required policy callback fails *before* `next_call` (exception, invalid outcome, or unavailable registration), propagate a typed admission error and never fall through to the provider. Preserve the existing downstream-exception propagation; do not turn denial into a response. Bind required policy to the Tensor custom-provider route and enforce presence on both CLI and gateway startup/reload (no silent skip when plugin load fails). The request boundary needs a testable, authenticated identity and shared lease/owner inventory that does not classify sleeping llama's existing CUDA context as an unrelated owner; the Stage 2 `safe_to_acquire()` currently requires `hermes-llama.service` inactive, so it cannot admit a sleeping active unit as-is. Keep the reservation through **all** model attempts, retries, streamed delivery and actual worker teardown; after last request, retain the lease until native 300-second sleep and confirmed VRAM release, then use the existing two-phase restoration path. Concurrent same-resource holders must not restore/unload each other's model. Unknown owners, missing evidence, or a competing embedding allocation must deny before a wake.

**Upstream acceptance tests needed:** denial/raise/missing-policy for both streaming and non-streaming branches must assert zero provider invocations; simultaneous incompatible and same-resource requests must assert serialized ownership and last-holder-only release; retries/interrupts/partial streams and delayed worker shutdown must not release a lease while transport still runs; native sleep with an active llama unit must safely distinguish its own residual allocation from unknown CUDA owners; restoration waits for confirmed VRAM release. Then run guarded live acceptance only after separately coordinated recovery. The current negative-characterization tests should fail when the upstream skip is fixed and should be replaced with positive veto tests, not interpreted as proof of a working gate.

**Rollback:** no production rollback; this branch adds only tests and documentation. A future upstream change should be reversible through its source commit, and any subsequent deployment needs a targeted snapshot of Tensor provider/unit configuration and the existing lease state without erasing pending work. Stage 3/4/5 production dispatch remains disabled.
