## Mail and receipt baseline

Nexus host has a live local Proton Bridge IMAP listener (`127.0.0.1:1143`). Read-only authentication with the existing `PROTON_BRIDGE_IMAP` Bitwarden secret succeeded, and mailbox `BODY.PEEK` searches did not mark messages read. All Mail held 4,491 messages at inspection; sender-domain searches found 102 Wealthsimple, 16 Metro and 838 CIBC messages. These are **mail counts, not proven transaction counts**. Only sender domains and redacted subject-category/template aggregates were used; raw mail and values were not printed or persisted. No mail parser, poller, or forwarding workflow was deployed.

Existing n8n has six workflows and three active, with receipt webhook/HTTP/code nodes but **no IMAP/Gmail mail-trigger node or mail credential**. Receipt Wrangler PostgreSQL has one receipt and two items; its established iPhone→text extraction→`receipt-text-ingest`→n8n/Receipt Wrangler path and dedup guard must be preserved. Separate `finance_analytics` PostgreSQL already has 16 validated `metro_email` purchase receipts and 73 item rows (none linked to Receipt Wrangler), zero `bank_activity_snapshot` and zero `receipt_transaction_matches`, plus existing `v_price_history` and spending views. This is a useful schema and initial price history, **not** a working cross-source matcher or current budget. The existing `receipt-match-reconcile` only suggests local associations; it does not populate analytics bank or match tables. Do not create duplicate purchase expenses when linking email and scanned receipts.
