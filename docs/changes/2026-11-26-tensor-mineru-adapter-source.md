# Tensor MinerU per-file adapter — source only

**Objective:** Use the existing typed GPU queue for distinct PDF work while preserving installed MinerU WebUI conversion and retained output conventions. The source-only `shared/scripts/tensor-mineru-adapter.py` stages bounded regular PDFs and creates one `mineru_pdf` record per content/config revision, with private manifest and stable job ID. It uses the existing queue worker lock and a caller-supplied admission context; it does **not** implement lease acquisition or start a second scheduler/service. No installed code or live PDFs were changed.

**Evidence:** The installed `mineru.kit.gradio.artifacts.create_run_artifacts()` on Tensor creates `output_root/gradio/<run>/middle_json.json`, `markdown.md` and `structured_content.json`. The existing conversion service calls `self.client.parse_file()` before `persist_parse_result()`. The dynamic router port is not a stable endpoint. Native parse tasks and the WebUI's conversion registry remain in their current implementation; this adapter is not yet connected to those call sites.

**Safety:** The queue now fences `mineru_pdf` from automatic retry after failure or lease expiry, because a native POST may have succeeded. This adapter persists a pre-call dispatch-unknown marker and, after conversion, an output root and three artifact SHA-256 digests before completing the queue record. A failed job may be explicitly reconciled only if that manifest and all retained artifacts match. Absence of a result marker after an ambiguous POST is **not** evidence the native task failed; a human must inspect native state and must not blindly resubmit the PDF. Protected source files, manifests and output are not public Git artifacts.

**Verification:** Four offline adapter tests passed: two distinct sequential PDFs/deduplication, unknown conversion outcome no replay, stale-lease artifact reconciliation, and symlink/changed-payload rejection. Twenty queue tests passed on the source branch. No native MinerU conversion, WebUI hook, GPU request, or restart was tested. The adapter has no CLI/deployed service, and `run_one(admit=..., convert=...)` requires a real GPU admission context and a callback using the installed conversion backend.

**Not production-ready:** Add/test a guarded WebUI/native conversion boundary shared by every PDF entry point, known-owner GPU admission, native task-ID durability/reconciliation, and protected runtime queue deployment before running PDFs. The source cannot guarantee exactly-once POST when the native response is lost. Do not enable production dispatch or change the WebUI service on this evidence alone.

**Rollback:** Revert these source files only. Do not delete staged PDFs, manifests, queue records or existing MinerU output runs. Before any future live migration, take a targeted protected backup of the queue and document the exact restoration procedure.
