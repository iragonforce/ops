# Read-only inventory and ownership baseline

Objective: consolidate agent/infrastructure management using existing tools and Git, beginning with a reviewed live discovery.

Hosts: qubit, tensor, nexus. Execution: Nexus with strict existing SSH routes. Tensor initially accepted authentication but stalled before opening a command channel. After the owner requested a recheck, hostname/kernel/user commands succeeded. No SSH, tmux or desktop configuration was changed by this implementation.

Captured metadata: Qubit 183, Tensor 291, Nexus 390 source/configuration/symlink entries. Consumer lists are static candidates; unresolved purpose/dependency classification remains a gate before retirement. Runtime/configuration/state observations are summarized in `docs/current/README.md`.

Checks: `hostname`, `uname -sr`, selected file metadata/digests; read-only SQLite table/count/FTS queries; selected Docker inspect mounts/labels and process UIDs; systemd show/timer/failed-unit reads; Git root/tracked-file/HEAD inspection; source inspection of native Hermes import/memory/search behavior. No formal tests, inference runs, message sends or service restarts.

Repository preparation: created private `iragonforce/ops` and isolated Nexus `~/ops` checkout on `consolidate`. Existing GitHub connector lacked private repository visibility; existing Bitwarden GitHub credential was used in memory through the native API. No new credential or plaintext credential file.

Limits: static inventory is not full execution tracing. Package wrappers need provenance classification. GitHub repositories other than ops/backup have not all been verified remotely. Existing Tensor failed units are unrelated pending issues.

Rollback: this commit adds source metadata/documents only and changes no running configuration. Preserve the repository/history if pausing; no runtime rollback needed.
