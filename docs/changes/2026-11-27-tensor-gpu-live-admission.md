# Tensor GPU live admission — November 27, 2026

## Objective and scope

Recover local Hermes prompting after the required middleware reported `Tensor GPU admission policy unavailable`; share Tensor GPU conservatively with queued embeddings using the existing SQLite queue, lease, worker lock, custom visual-standby signal and systemd. Do not purge unknown VRAM owners, replay ambiguous PDFs, or move private input/output into public Git.

## Actual changes

- Installed `tensor-gpu-admission` as the required local llama.cpp/Ollama `llm_execution` middleware. A positive lease is acquired *before* starting llama; preflight, unknown-owner and activity vetoes remain fail-closed. Plugin provides the fixed metadata-only `tensor_gpu_status` and `tensor_local_models` tools in `tensor_readonly`. Both local routes are protected by the pinned upstream middleware patch plus `shared/patches/tensor-hermes-ollama-admission.patch`; remote/other providers are outside that contract.
- Replaced Tensor's divergent `~/.local/bin/hermes` wrapper with the already Git-owned wrapper after observing an active, unleased llama process. Cleared llama's independent `ExecStopPost` wallpaper restoration so the existing lease owns restoration. Retained the native 300-second sleep setting, although the current plugin stops the llama unit at the end of each request to release VRAM. Changed `agent.reasoning_effort` from `minimal` to `low` and local Ollama provider base URL to `http://127.0.0.1:11434` in protected runtime config.
- Installed four existing queue/lease/probe/desktop components under `~/.local/share/tensor-gpu/` and added an optional blocking worker lock (default remains nonblocking). Installed `tensor_gpu_embedding.py` there with protected input/result files, a transient systemd user worker, local `/api/embed`, bounded retry, model-unload observation, and lease release only after unloading. A pending PDF ahead of an embedding blocks this worker until the separate PDF integration exists. Queue pause blocks dispatch. This is not a new persistent daemon.
- Local Ollama catalog on November 27 contained `qwen3-embedding:8b-fp16` and `qwen3.5:27b`. The plugin checks installed names and refuses to force-stop a potentially shared Ollama model; an Ollama chat can wait up to six minutes for native idle unload, then retain its lease and fail closed. Chat acceptance has **not** passed. Direct :11434/:7860 clients and Tailscale Serve 8445 remain accessible from the earlier completed restriction rollback; they can bypass queue admission.

## Checks and results

Python compile and source/live hashes matched after deployment; `hermes plugins doctor` passed and gateway `/health` returned HTTP 200 after restart.
- Multiple real default local Hermes one-shot requests exited 0 after the wrapper/config recovery. Standalone admitted callback returned its provider result; llama subsequently inactive, zero lease holders and normal mode. This is more than gateway-health-only acceptance, but did not prove interactive wallpaper active→stopped→restored or model-driven tool invocation.
- The worker completed one local queued test input, job `435df7bf-d273-4ff1-a3ee-170bfe7be062`, with the expected revision, canonical input digest, one 4096-dimensional finite vector and no vector content printed. Afterward the job read back as complete, lease was normal with no holders, worker was inactive, llama was inactive and Ollama residency empty. A targeted SQLite backup `queue.before-worker.sqlite3` was created with SQLite's backup API before this sample.
- Strict-key SSH from Nexus user `iragonforce` and from the Hermes container to Tensor worked. Nexus's existing `qdrant-memory.service` received a scoped Git-owned drop-in retaining its timer/collection/checkpoints and all four host/container phases. Its worktree source uses the protected SSH handoff and a 900-second bounded background wait. `systemd-analyze verify` passed; parsed environment is a valid JSON argv and the unit remained inactive after installation. A first manual writer attempt (before the longer wait) met an independently resident Ollama embedding model, timed out at 30 seconds and left a pending Tensor job, with **no Qdrant upsert or cursor advance**. The worker waited instead of force-stopping unknown GPU ownership; after native idle unload, that job completed. The same Nexus writer then retrieved one 4096-dimensional vector through the configured SSH command, upserted an existing public-ops point, read back its exact ID/content hash/vector and restored the original point from its protected before-image. Tensor readback showed two completed jobs, zero lease holders, normal mode and no resident Ollama or llama model. Read-only Nexus preflight found inbox changed=0/stale=0; ops changed=0/four stale points are intentionally retained. **MinerU conversion and TTS dispatch have not been verified.** No dedicated Tensor TTS unit was identified. Arrival-order semantics across all four clients remain incomplete; the existing queue's priority ordering is not strict global FIFO.
- The existing Hermes MCP server configuration was updated using native `hermes config set` (after a protected exact config backup): its source argv points at this Git task worktree and `QDRANT_MEMORY_EMBED_COMMAND` is a `json:`-prefixed JSON argv string because native config coercion otherwise stores a YAML list, not an environment string. A fresh `hermes mcp test qdrant_memory` discovered both tools and a fresh process ran a source-cited `ops` query using queued local embedding without printing the retrieved passage. A running TUI/MCP process may still need `/reload-mcp` or a new session to load the new config; no gateway restart was performed. A protected Tensor config before-image was saved and the supported config CLI changed that key to `http://127.0.0.1:11434/v1`; the gateway was restarted and remained active. The next chat request reached Ollama but waited behind its default five-minute post-request model residency, exceeding the bounded CLI test. The GPU lease remained reserved during its wait, then released on unload; no unknown model was force-stopped. With Ollama idle and zero lease holders, the existing Git-owned system service override was backed up as `/var/lib/tensor-gpu-admission/ollama-override.before-keepalive.conf`, then extended with `OLLAMA_KEEP_ALIVE=0`. `systemd-analyze verify`, daemon reload and a bounded service restart passed; `/api/tags` returned HTTP 200. A real one-shot local Ollama request then returned `Ready!` (exit 0), followed by empty `ollama ps`, zero lease holders and normal GPU lease state. This default also changes model residency for direct Ollama clients; explicit request-level keep-alive can override it. The desktop was in visual standby throughout, so active wallpaper restoration was not demonstrated.
- A bounded local Ollama model-tool prompt discovered `tensor_local_models`, invoked it and received the installed names `qwen3-embedding:8b-fp16` and `qwen3.5:27b`. The session did **not** deliver its final answer within the bound. After `ollama ps` was empty and the sleep-aware backend independently verified all GPU owners/memory released, an explicit `LeaseManager.reconcile()` returned `normal`; subsequent readback showed zero holders. No model was force-stopped, but multi-turn model-tool completion and automatic recovery from this race are **not accepted**.

## Rollback and recovery

- Protected Tensor before-images: `~/.local/state/tensor-gpu-admission/hermes-queue-cutover/{30-native-sleep.before.conf,hermes-wrapper.before,hermes-config.before.yaml,hermes-config.before-ollama-v1.yaml,middleware.before-ollama.py,plugin.before-ollama.py,hermes-config.before-ollama.yaml,plugin.before-safe-unload.py,queue.before-worker.sqlite3,embedding.before-mcp.py}` and root `/var/lib/tensor-gpu-admission/ollama-override.before-keepalive.conf`. The earlier `hermes-gateway-cutover/` contains the original middleware and gateway drop-in. Nexus host protected `~/.local/state/tensor-gpu-admission/nexus-cutover/` holds the first unit drop-in and a targeted exact Qdrant point before-image (restoration was verified). Hermes container protected `/opt/data/state/tensor-gpu-admission/nexus-cutover/config.before-qdrant-mcp.yaml` holds the pre-change MCP config. Do not copy live SQLite files while open or delete queued payloads/results.
- **Nexus unit rollback** (when inactive): `sudo rm /etc/systemd/system/qdrant-memory.service.d/30-tensor-gpu-embedding.conf && sudo systemctl daemon-reload && sudo systemd-analyze verify qdrant-memory.service`. This removes only the new drop-in, reverting to the original Git-owned unit and old direct embedding behavior; it does not delete Tensor's pending jobs or alter Qdrant state. Do not remove the isolated worktree while the unit still references it.
- **Hermes MCP rollback:** restore only `mcp_servers.qdrant_memory.args` and remove `mcp_servers.qdrant_memory.env.QDRANT_MEMORY_EMBED_COMMAND` using the native `hermes config` CLI, then reload MCP in a fresh session. Compare with the protected `config.before-qdrant-mcp.yaml` without printing it. Do not restore the whole file blindly over unrelated live credentials/session changes.
- **Ollama rollback:** first confirm `ollama ps` is empty and no active request/lease exists; `sudo install -o root -g root -m 0644 /var/lib/tensor-gpu-admission/ollama-override.before-keepalive.conf /etc/systemd/system/ollama.service.d/override.conf && sudo systemctl daemon-reload && sudo systemctl restart ollama.service`. This reinstates Ollama's old idle retention, so subsequent Hermes Ollama responses can wait for its normal unload; do not use a force-stop against active models. The Hermes Ollama endpoint can be restored independently with `hermes config set providers.ollama.base_url http://127.0.0.1:11434` followed by gateway restart, but that knowingly restores the prior HTTP 404 for local chat; prefer the working `/v1` path.
- **Safe deny-only rollback**, after checking no active request/lease: on Tensor, `hermes plugins disable tensor-gpu-admission --no-allow-tool-override` then `systemctl --user restart hermes-gateway.service`. The required middleware continues to deny protected local inference instead of bypassing admission. Do not restore the old wrapper or the old gateway dependency as an automatic fallback; either could reintroduce unleased startup or the failed-llama gateway coupling.
- If the worker needs isolation, stop only `tensor-gpu-embedding-worker.service` after checking its status and preserve `~/.local/state/tensor-gpu-queue/` plus `~/.local/state/tensor-gpu-lease/`. Do not manually mark an ambiguous PDF request retryable. Once the cause is fixed, a subsequent submit/result poll can restart the transient worker; reconcile durable state before any replay.

## Remaining acceptance

Nexus's timed writer and fresh Hermes MCP processes are switched; ad-hoc writers and any already-running MCP process may still use direct Ollama until explicitly reloaded. Native MinerU PDF dispatch/result retention, actual interactive desktop restoration and user-activity gating, completed multi-turn model/tool response and automatic fail-closed admission reconciliation, and global FIFO across workload kinds remain unverified or unimplemented. This record describes an operational partial deployment, not a completed all-workloads cutover. Source branch: `feat/tensor-gpu-stage3`; Git revision is the commit containing this record.
