# Qdrant Memory — three-host SSH ingress (v2)

## Architecture

The existing Nexus-only `~/ops/shared/scripts/qdrant-memory.py` remains the writer for `qdrant_memory`. Nexus Qdrant is not exposed over the network. The original Nexus inbox at `~/qdrant-inbox` and the existing system-level `qdrant-memory.service`, `.path`, `.timer` remain unchanged.

Each host has identical entrypoint `~/.local/bin/qdrant-memory` and an inbox at `~/qdrant-inbox`. New frontend `shared/scripts/qdrant-memory` dispatches locally on Nexus, over authenticated SSH (`nexus`) from qubit/tensor. New Nexus receiver `shared/scripts/qdrant-memory-remote.py` validates each transfer and writes an atomically named host-scoped `.md` copy into the existing Nexus inbox. It calls the existing, validated indexer to embed on Tensor (`qwen3-embedding:8b-fp16`) and upsert to Qdrant on Nexus.

Inbox watcher implementation follows the OS:

- Nexus: retain existing systemd system units `qdrant-memory.service`, `qdrant-memory.path`, `qdrant-memory.timer`.
- Tensor: systemd **user** units with these same three names, generated by `qdrant-memory-watch-setup.py`.
- Qubit: `~/Library/LaunchAgents/com.blinkwired.qdrant-memory.plist` (macOS has no systemd), generated by the same setup script. The launchd agent watches the inbox and reconciles every 900 seconds.

## Commands (same on all hosts)

```sh
qdrant-memory init --host nexus     # Nexus only
qdrant-memory init --host tensor    # Tensor only
qdrant-memory init --host qubit     # Qubit only
qdrant-memory status
qdrant-memory update notes.md      # inbox file, if present
qdrant-memory update /absolute/path/to/notes.md
qdrant-memory update /absolute/path/to/script.py  # wrap code as Markdown, no execution
qdrant-memory update ops
qdrant-memory update nexus
qdrant-memory update tensor
qdrant-memory update obsidian
qdrant-memory update repo owner/repo
qdrant-memory update repo https://github.com/owner/repo
qdrant-memory update repo owner/repo --dry-run
qdrant-memory sync-inbox --dry-run
qdrant-memory sync-inbox
qdrant-memory sync-inbox --allow-empty  # explicit deletion of all previously synced host inbox files
```

`update ops/nexus/tensor/obsidian` always runs against Nexus's **existing** checkouts and vault. It does not fetch a remote. For arbitrary public GitHub repos, `update repo <GitHub URL>` performs a shallow `--no-checkout` clone into a Nexus temporary directory, reads only committed Git blobs (never executes them), indexes an isolated `origin=git_repo_ephemeral` with commit SHA/branch/source metadata, and deletes the temporary clone after completion. It does **not** automatically prune previous indexed passages from an externally cloned repo; old points remain labeled with their original commit. Managed `iragonforce/ops`, `nexus`, and `tensor` URLs are routed to the existing authoritative/snapshot indexers to prevent duplication.

## File synchronization and deletion

Only `.md` / `.txt` in `~/qdrant-inbox` trigger **automatic** sync on all hosts. Explicit `qdrant-memory update FILE` additionally supports selected UTF-8 source-code/configuration suffixes. Files must be regular files, <=256 KiB, without NUL bytes, and are screened for recognizable credential patterns. Screening is a heuristic, NOT a guarantee of secrecy. Do not place secrets or personal files in the inbox.

On clients, each watched file gets a stable host-prefixed filename in Nexus's existing flat inbox (for compatibility with `qdrant-memory.py`). The original stays on the source host. Text is copied, not moved, and is stored as the plain-text payload of Qdrant vectors. Individual ad-hoc `update /path/...` uploads are separate from the watched file manifest.

Host-specific manifests under Nexus `~/.local/state/qdrant-memory/client-manifest-{qubit,tensor}.json` track only automatically synced files. Removing a watched file on qubit/tensor causes a scoped deletion of **only the file's corresponding manual_inbox records** on Nexus. Empty-manifest and large-prune guards prevent accidental mass deletion. Ad-hoc files, other host files, OPS/Git/Obsidian records are not deleted by the client watcher. A full client inbox must be intentionally emptied with `sync-inbox --allow-empty`.

The client SSH transfer is initiated with `BatchMode=yes` so watchers never block waiting for password prompts. Configure authenticated SSH alias `nexus` before activating watchers. No inbound ports on qubit/tensor, no extra containers, and no public Qdrant API are introduced.

## Install staged source and rollback

First install the 3 scripts in the Nexus `~/ops/shared/scripts` source tree without replacing the existing `qdrant-memory.py`. Validate `python3 -m py_compile` and test `shared/scripts/qdrant-memory status`. Existing Nexus CLI is a symlink to `qdrant-memory.py`; replace only the symlink with an atomic symlink switch to `~/ops/shared/scripts/qdrant-memory`, and retain a copy/record of the previous symlink in `~/ops/docs/backups/qdrant-memory-v2-<timestamp>/`. Rollback: restore the previous symlink to `qdrant-memory.py`; no Qdrant data change necessary.

On each client, copy these **same** `qdrant-memory` and `qdrant-memory-watch-setup.py` scripts to `~/.local/bin` (files should be chmod 700). Run `qdrant-memory init --host qubit|tensor`, then `qdrant-memory status`, `qdrant-memory sync-inbox --dry-run`, and a manual one-file transfer. Only after successful tests run `qdrant-memory-watch-setup.py --install`. To disable on tensor: `systemctl --user disable --now qdrant-memory.path qdrant-memory.timer`. To disable on qubit: `launchctl bootout gui/$(id -u) ~/Library/LaunchAgents/com.blinkwired.qdrant-memory.plist`. Neither command removes indexed Qdrant text.

Important: these scripts were tested locally with synthetic fixtures, not against the live three-host SSH/authentication or model environment. Deploy one host and verify actual results before continuing.
