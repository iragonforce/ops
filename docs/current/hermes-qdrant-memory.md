# Hermes → Qdrant historical findings

Scope: default Hermes profile only. The main session database at container `/opt/data/state.db` (Nexus `/srv/containers/data/hermes/data/state.db`) is opened in SQLite read-only/query-only mode. The exporter `shared/scripts/hermes-compaction-export.py` selects parent sessions with `end_reason=compression` and summary-marked messages in their child sessions. Incomplete parent/child lineages are ignored until a later sync; a single read transaction gives the lineage query a consistent snapshot. Existing profiles' databases, `MEMORY.md`, `USER.md`, compression engine, and existing Qdrant origins are untouched.

`shared/scripts/qdrant-memory.py sync-hermes` uses the existing Qdrant collection and Tensor `qwen3-embedding:8b-fp16` model (4096 dimensions). It splits summary sections into individual Markdown list items, rejects oversized, multi-topic, sensitive, personal/financial and ambiguous items, and requires an exact public Git-tracked source path before indexing. Both existing credential expressions are applied. Rejected items are counted by reason but their text is never logged; they remain in the original protected session store only. This deliberately sacrifices recall rather than auto-publishing unreviewed private summary contents. A Git path is a traceability gate, **not proof that an agent assertion was true**. All indexed points are tagged `agent_summary_historical_unverified`, `historical_only=true`, low confidence, original observation date and session/compaction/message IDs. Before acting, consult current ops documentation and inspect live state. A path and a summary do not establish current configuration.

Each record uses a deterministic UUID based on the lineage and item ordinal, a SHA-256 hash of the screened text, and `origin=hermes_session`. The separate origin is filtered independently. Embedding batches are bounded to three; Qdrant upserts wait for acknowledgment and are read back before the per-compaction checkpoint advances. The checkpoint is an atomic, mode-0600 JSON file under the private Hermes container state path `/opt/data/state/qdrant-memory/hermes-compaction-checkpoint.json`; it contains IDs only, no transcript. A process lock in the same mode-0700 directory rejects concurrent runs. Reconciliation compares IDs/hashes with Qdrant even after checkpoint completion, so interrupted upserts or missing points retry. No automatic pruning occurs. Qdrant or Ollama failure leaves the checkpoint at the last confirmed compaction; the next scheduled run retries. Do not expose private session data through the manual inbox or public Git.

The existing Nexus `qdrant-memory.timer` (every 15 minutes after previous inactivity, plus the existing path watcher) starts `qdrant-memory.service`. The existing inbox command still runs as `iragonforce`; an `ExecStartPost=+` command uses root only to enter the **existing** `hermes` container, executing the new sync as UID 10000, which owns the session database. The container uses `http://qdrant:6333`; the host inbox still uses its existing localhost endpoint. This is not a new scheduler or service. If the inbox command fails, systemd skips ExecStartPost and the next timer run must recover; monitor the unit result. The MCP source `shared/scripts/qdrant-memory-hermes-mcp.py` deploys to `/opt/data/mcp/qdrant-memory-hermes-mcp.py` in the container; it must admit `hermes_session` or the tool silently filters out those results. New TUI sessions discover the updated MCP schema; an existing session may need `/reload-mcp`.

Operator checks: `sync-hermes --dry-run` requires `QDRANT_MEMORY_INDEXERS`, `QDRANT_MEMORY_OPS`, and `QDRANT_MEMORY_QDRANT` set to the container paths/URL when run inside Hermes. Live automated runs use the unit's explicit environment. Review only protected staged findings, never whole summaries or transcripts in terminal logs. Qdrant `/points/count` with an origin filter and `/points` exact IDs verify write effects; `knowledge_search` with `origins=["hermes_session"]` and `knowledge_read` verify retrieval and provenance. A deliberately conservative selector may index **zero** findings from a compaction; that is safer than treating an unverified statement as an approved fact.

Rollback: disable only the `ExecStartPost` integration by restoring the previous `qdrant-memory.service` from the parent Git revision and reloading systemd; restore the previous MCP source from its protected pre-deployment copy. Restore the old `qdrant-memory.py` from Git. Preserve the SQLite database and checkpoint for investigation. To remove only this project's points, enumerate exact IDs through the protected checkpoint and origin-filtered Qdrant scroll, confirm `origin=hermes_session`, then delete those explicit IDs with Qdrant `/points/delete?wait=true`. Never delete the collection or other origins; do not run a collection-wide prune. See the dated change record for actual deployment and verification status.
